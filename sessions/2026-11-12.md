# 2026-11-12 — agx32 disk cleanup and uplift retention

## Outcome

`agx32` root filesystem was at 99% (869G/916G used, 9.4G free). It is now at
8% (70G/916G used, 809G free). The live Qdrant index, the model stores and the
knowledge vault were preserved; only transport, stale copies and an orphaned
spool were reclaimed.

### Root disk

- **Qdrant snapshots:** 426G in the container writable layer, 4 collections ×
  ~280 snapshots from a 15-minute timer, against a 1.8G live index. Kept the
  newest snapshot per collection (4 files, 1.5G) and deleted the rest.
- **Uplift outbox:** 162G of 832 orphaned `.bin` payloads with no matching
  `.json` row. Wrote `outbox-manifest.txt` and deleted them; the outbox is now
  84K.
- **Console crash loop:** `sparknet-console@master.service` restarted 18,083
  times because `/home/raxxar/sparknet/master-node/.state/webui/console.token`
  was missing. Stopped and disabled it; the peer console remains active.
  Truncated `syslog`/`kern.log`/`auth.log`, vacuumed the journal; `/var/log`
  went from 2.8G to 2.4M.
- **Uplift snapshots and backups:** deleted `/srv/sparknet/uplift/snapshots`
  (39G) with a 1,974-line manifest; moved `/srv/sparknet/backups` (2.9G) and
  nine old worktree tarballs (25M) to `/mnt/ai/cleanup-2026-11-12/`.
- **Docker:** pruned nine exited containers (~6.6MB). Images were not pruned:
  the 20.47GB "reclaimable" is tagged runtime and rollback images
  (`sparknet-opencode-runtime:2.2.5`, `ollama/ollama:rollback-03213`).
- Added `maxsize 100M` to the `syslog` logrotate stanza (backup alongside it).

### Data disk consolidation

- Merged the stale root Ollama store into the active `/mnt/ai/ollama/models`.
  All 72 source files were verified by relative path and size; the merged store
  lists 33 models. The 138G root copy was then removed.
- Copied `~/.cache/huggingface` to `/mnt/ai/hf-cache`; all 63 files verified by
  relative path and size. Replaced the directory with a symlink and removed the
  31G root copy.

### Retention fix

`scripts/sparknet-uplift-push.py` now keeps the newest snapshot per collection
(`--keep-snapshots`, default 1), deletes the rest, dedupes spooled payloads by
sha256, sweeps unreferenced `.bin` files, caps the outbox at 5 GiB (oldest rows
dropped first), and refuses to snapshot when the snapshot directory is on the
root filesystem. `peer-node/configs/ai-stack/docker-compose.qdrant.yml`
bind-mounts `${SPARKNET_QDRANT_SNAPSHOT_DIR:-/mnt/ai/qdrant-snapshots}` to
`/qdrant/snapshots`. Qdrant was recreated with the node env file; all five
collections survived, `healthz`/`readyz` are 200.

Commits: peer `6ba5ab5`, fabric `c846e03` (including the submodule pointer and
`tests/test_uplift_push.py`, 8 tests).
