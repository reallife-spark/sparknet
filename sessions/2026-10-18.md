## The seven defects only a bare clone could show

Every one was invisible locally, mostly for the same reason: **this host's
system `python3` has `cryptography` installed, and `.venv` already existed.**

1. **`make devtools` never worked on a fresh clone.** It passed `$(VENV_PY)`
   (`.venv/bin/python`) to `python3 -m venv`, whose argument is the *directory* —
   so it built a venv *inside* `.venv/bin/python/` and the next line exec'd a
   directory (`Is a directory`, Error 126). Same bug in `peer-node/Makefile`
   and `chroma-dev`. `pyvenv.cfg` on a fixed tree records
   `command = … venv /…/.venv`.
2. **The workflow installed requirements into the runner's system pip** while
   `VENV_PY` resolved to the repo `.venv` → every subprocess test died on
   `.venv/bin/python: No such file`. Replaced with `make devtools` (the repo's
   own bootstrap) + pip cache keyed on both requirements files.
3. **Role targets fell through to system python.** `PY := own .venv, else
   python3`, and neither role has an `.venv` in a checkout → master's `ledger`
   target exited 2 during `validate`. `PY` is now *own venv → fabric venv →
   python3*; the two peer targets shelling `sparknet-run python3 …` pass
   `$(PY)`.
4. **Tests spawned bare `python3`** (8 sites in `peer-node/tests/test_scripts.py`,
   plus the shared-CLI help test) → `cryptography` missing; keygen silently
   produced wireguard keys and **no Ed25519 pair**. Fixed to
   `sys.executable`, and `gate.yml` now puts `.venv/bin` first on `$GITHUB_PATH`
   for the job so shell scripts driven by tests (keygen, validate) find it too.
5. **Per-vault `.env` is gitignored by design**, so a fresh clone has none and
   `test_the_wiki_suite_resolves_this_role_as_its_own_vault` correctly refused
   to pretend. `gate.yml` now runs `make env-init` (documented one-time
   bootstrap; idempotent, covers all three vaults).
6. **shellcheck had never run anywhere.** The step self-skips when the binary
   is absent, and it is absent here — runners have it, and it found 44
   findings. The **7 warnings were fixed** (dead `--capabilities` on
   `registry-revoke.sh` + its Makefile caller; dead `CL_PUB`/`M_PUB`; dead
   `--verbose` on sync; two `export VAR="$(fn)"` masking return values in the
   entrypoint; an SC1090 directive that didn't reach its command because three
   commands sat on one line); the 29 info/style findings are **waived
   explicitly** in `.shellcheckrc` with a reason each — deliberately not by a
   severity floor, which shellcheck only honours on the CLI, so a new release
   that reports something new still fails the gate.
7. **codeql 403 then a plan wall.** First `Resource not accessible by
   integration` (missing `actions: read`, needed for `analyze()` to read its
   own run) — fixed in both repos; `tests/test_ci.py`'s permission vocabulary
   widened to allow it **only** on `codeql.yml`. Then the real blocker:
   **GitHub only scans public repos on the Free plan** (Code Security is paid
   on private). After confirming that against the docs and the live API, the
   user chose **self-skip**: a preflight reads
   `security_and_analysis…status`, emits a `::notice` explaining what's
   missing, and gates `init`/`analyze` (and `setup-go`) — green and explained,
   never silent; it becomes a real analysis the moment the repo goes public or
   Code Security is enabled.

## Decisions

- **A5 unchanged**: local `make ci` stays authoritative; the runner mirrors it.
- **codeql → self-skip with notice** (user choice, options were skip / delete /
  leave red / pay).
- **Branch protection is unavailable on this plan** (needs Pro or public) — so
  no check is required; recorded in `MEMORY.md` open items.
- Info/style shellcheck findings waived **explicitly**, not by severity floor.

## Gotchas (tooling, for next time)

- The shell tool's **120 s default timeout kills `make ci`** mid-run
  (`Terminated` ≠ gate failure); run it as `timeout 1800 make ci >file 2>&1`
  in background and poll the file.
- `gh` is at `~/.local/bin/gh` (not on a non-interactive `PATH`), authenticated
  as `reallife-spark`; `checks:read` can't be granted on a PAT, so annotations
  403 — use `gh api repos/…/actions/jobs/<id>/logs` and pass
  `--allow-escape-sequences` or `gh` refuses to print the log.
  `gh run download` fetches *artifacts*, not logs; `gh run view --log-failed`
  can hang on big jobs.
- Sandbox rule set denies `rm -rf` on a list of system paths — use a fresh
  `mktemp`-style dir instead of clearing `/tmp/opencode/…`.
- Docker has no `.opencode/skills`-aware shellcheck image problem: use
  `koalaman/shellcheck:stable` (0.11.0) — `:0.9.0` doesn't exist.
- Bare-clone simulation that actually works:
  `git ls-files -z | xargs -0 -I{} sh -c 'mkdir -p "$2/$(dirname "$1")" && cp …'`
  (plain `cp --parents` chokes on the role shims/symlinks).
