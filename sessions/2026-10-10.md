### Design decisions locked

- Grants verified by `authz.verify_grant` only; guard order restated once in
  the identity schema and never re-implemented (DoD 1).
- `grant_use` blocks = the same dual-signature envelope as approvals
  (DoD 1/2), so `verify_approval_blocks` / contract-test cover them with no
  new verification code.

  id (avoids a two-pass write; the grant key joins them).

### What it is

`peer-node/services/sparknet-share-regime.py` — a pure, in-process,
message-dispatched state machine (`share.offer/accept/ratify/use/reconcile/close`)
that takes the **machine contracts** as its only rule source and refuses to run
without them, the same anti-drift discipline the guard and the authz ladder
use. `contracts/capabilities.json` supplies `share_types` + `share_clocks`;
`contracts/overlay.json` supplies `governance_mode` + the data-plane stanza
fields and the authority-plane one-address rule; `contracts/ports.json`
supplies the (spec-only) share ports.

- **Clocks** default from the contract — 1 h accept, 20 m idle, 2 h
  ratification (master_governed only), 10 h absolute — and are **clock-injected**,
  so tests that would take hours run in seconds (DoD 4).
- **Governance** is recomputed from the registry node count on every request,
  never cached: `solo` (drafts allowed, acceptance refused), `peer_pair`
  (symmetric, both endpoints `flagged`, a Master arbitration refused
  `no-arbiter`), `master_governed` (3+) where a Master `ratify` moves both
  endpoints to `authenticated` with `flagged` retained. A third node joining
  mid-share **re-evaluates** the live share rather than grandfathering it.
- **Transport** is a time-boxed **data-plane** stanza + nftables fragment, torn
  down on close/idle/expiry, leaving the **authority-plane one-address
  `AllowedIPs` invariant** (`10.100.0.1/32`) intact. Non-ratification severs the
  fabric data plane; peer-to-peer continues; every share ends at 10 h.

## Step 21 complete — reduced-membership re-formation + live cross-node root sync

The two Step 16 halves that stayed spec-only are now built, as **option B full**
(the operator's choice): this *adopts a reduced-membership re-formation policy
the contract had previously declared unspecified*, so the DoD included
reconciling the contract and design doc to match the built behaviour.

### What landed

- **Schema 1.2** (`shared/sparknet-consensus.py`): a new **signed** `epoch`
  field (genesis 0, chained = parent+1, clock-free — it is what distinguishes a
  genuine next generation from "the same lockstep"), and a **version-aware
  signed-field set** (`ROOT_SIGNED_FIELDS_V1` / `_V11` / `_V12`) so each schema's
  roots verify against their original bytes and ids. A live 1.1 root is epoch 0,
  so it can parent the first 1.2 re-formation.
- **Removal proofs** — carried *alongside* a chained reduced root but **not one
  of its signed fields** (each independently signed, keeping member
  co-signatures small). Kinds: `revocation` (parent Master's *operational* key —
  the contract's 1-signature revoke made durable) and `attested` (every
  survivor's *cluster* key = majority-to-reduce). New primitives
  `canonical_removal_proof` / `removal_proof_bytes` / `sign_removal_proof` /
  `verify_removal_proof` / `_removal_proofs_by_member`.
- **Trust path** (`verify_root`) now checks, in order: replay → chained
  (`previous_root_id == root_id(parent)`) → **epoch** (`child.epoch ==
  parent_epoch+1`) → subset (no add) → floor (`MIN_CLUSTER_SIZE=2`; a lone
  survivor holds only a tombstone proof, not a cluster) → **exact-removal**
  (`dropped = parent_ids − child_ids` must equal the evidenced set exactly, each
  proof's `parent_root_id` matching). New reasons `missing_removal_proof`,
  `bad_removal_proof`, `unexpected_removal_proof`; a wrong epoch is
  `unchained_root`.
- **Election module** (`shared/sparknet-election.py`): `build_root(...,
  previous_root_id, epoch, removal_proofs)` and `ElectionExchange.__init__` pass
  them through; `serve(..., trust_root, removal_proofs)` derives
  `previous_root_id = root_id(held)` and `epoch = held.epoch + 1` via the new
  `_load_held_root`; CLI `serve` gained `--trust`/`--removal-proofs`. The
  `accept` subcommand is the peer-side root consumer (writes the identity
  `trust_root`; `accepted=True` only when `node_id == master_node_id`).
