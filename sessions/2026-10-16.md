## Fabric Step 44 — goSpark / spark.docker interop (complete)

The problem this step answers: goSpark and the fabric were siblings that merely
co-existed. Where they meet (a node's signed identity, the registry it verifies
against, the ports it exposes, the goSpark knowledge binaries, the foreign
images it pulls) nothing proved they agreed. Step 44 makes the seam explicit and
tested.

### 1. Cross-language authority — `tests/test_registry_crossverify.py`

Drives the **real** goSpark binaries (`sparknetctl`, and the fabric's
`shared/sparknet-authz.py`) against each other. Pins:

- identical field names (`fingerprint`, `identity`, `capabilities`,
  `overlay_ipv4`, `issued_at`, `expires_at`, `revoked`, `signature_b64`; doc
  `schema_version`, `master_public_key_b64`, `authorizations[]`);
- identical canonical envelope **bytes** — Python
  `json.dumps(sort_keys=True, separators=(",",":"))` matches Go
  `apiv1.CanonicalJSON`;
- identical fingerprint fields (`node_id, role, wireguard_public_key_b64,
  overlay_ipv4, requested_capabilities`).

Deliberate asymmetry, recorded not "fixed": goSpark's `private_key_b64` is the
64-byte seed+pub, the fabric's `load_private_key` wants a 32-byte seed. Only
**public** keys cross the boundary, so it cannot affect a join; pinned by
`test_private_key_encodings_differ_by_design` so a future "alignment" cannot
quietly change the crypto-loading path.

### 2. Join a running fabric — `--master-pub` / `--registry`

A node can now adopt an already-elected Master instead of forming its own root:

- `render_env_file` emits `SPARKNET_MASTER_PUB` (pinned key, else derived) and
  `GOSPARK_REGISTRY_FILE` (staged registry path); compose `x-spark-env` passes
  both to every service.
- `act_up` re-renders whenever join inputs are (re)specified, so an already-up
  node can be joined without hand-editing the env-file.
- `spark-entrypoint.sh master_pub()` **fails closed**: a registry staged with no
  pinned key is a hard error, never a silent empty verification key.
- `--registry` with `--role master` is refused (a Master does not adopt another
  Master).
- Runbook §6 documents the whole path; later sections renumbered.

### 3. Node ports documented — `contracts/ports.json` `node_ports`

The node's 14 numbers now carry honest axes (`host_published`, `host_bind`,
`container_port`, `compose_service`, `profile`, `implementation_state`,
`runtime`, `runtime_why`) plus `collision_note` where a number collides with a
fabric one. Three invariants lock the intent, and the renderer projects the
table into `contracts/manifest.json`. Drift tests bind the declaration to what
compose actually publishes and keep the node and fabric namespaces apart — the
fabric's `opencode-serve` 4200 stays `spec-only` (a fabric test enforces it)
while the node's 4200 is declared separately. The `node_measurement` block
records the real same-host collision found here (the raxxar Aegis cluster owns
4222/8222/8000).
