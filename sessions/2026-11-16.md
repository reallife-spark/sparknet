## Code foundation

- `shared/sparknet-sso.py`: group→role mapping, caller `X-User-*` stripping,
  override validation/precedence, Master→node assertion verification,
  node-signed offline-repair verification. No crypto of its own.
- `shared/sparknet-authz.py`: two new envelope kinds, `sso-assertion` and
  `offline-repair`; the repair builder refuses any nested capability, registry,
  trust root, grant, key or approval field.
- `peer-node/services/sparknet-auth-gateway.py`: loopback `auth_request`
  backend using `shared/sparknet-http.py`; accepts a verified OIDC session
  (via the local oauth2-proxy), a client certificate, or a Master assertion;
  injects only the trusted headers; records `role-override-conflict` events.
- `peer-node/services/sparknet-dispatch-bridge.py`: a successful signed
  `set_user_role` now writes the 0600 per-node override file.
- `webui/nginx.sso.conf.template` and peer/master `docker-compose.sso.yml`:
  TLS-only ingress, optional client cert against the admin CA, `auth_request`,
  and explicit stripping of caller `X-Auth-Request-*`. Base compose switches
  templates through `SPARKNET_NGINX_TEMPLATE`.
- `master-node/services/sparknet-admin-proxy.py`: registry-only target
  resolution (URLs refused), short-lived signed assertion, mTLS transport.
- Tests: `tests/test_sso_identity.py`, `tests/test_envelopes.py`,
  `peer-node/tests/test_auth_gateway.py`,
  `peer-node/tests/test_admin_supervise.py`,
  `master-node/tests/test_admin_proxy.py`. `make test-all` green (678 peer

  `shims-check` green.
