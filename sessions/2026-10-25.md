## Decisions (operator, before code)

- **Fork 1 — answer transport only; defer the request direction honestly.** A
  peer→Master *request* is signed with the peer's node key, but **nothing binds a
  peer fingerprint to a node signing public key** — `authz.sign_authorization`
  puts the fingerprint + WireGuard key in a registry entry, not an Ed25519 node
  key. So the Master cannot attribute a request signature and `verify_rfi_request`
  does not exist. Inventing that binding is a contract change and its own step.
  The composer takes `request_id` + destination peer as inputs instead. The reason
  is recorded in `rfi-schema.json` `implementation_state.request_channel` so it
  cannot be silently dropped.
- **Fork 2 — the composer signs through the isolated signer too**, not only
  `--offline`. Added a `sign-rfi-answer` op to `sparknet-signer.py`.

## What was built

- **Listener (peer):** `POST /api/v1/rfi` is a *third route on the guard's 9090*,
  not a new port — `handle_rfi` in `peer-node/services/sparknet-guard-d.py`,
  behind the guard's source gate / size limit / refusal vocabulary, installing
  through `shared/sparknet-rfi-install.py::accept_answer` (the one rule). Not
  gated on the peer's capability (like the registry route). `RFI_REFUSAL_STATUS`
  maps each contract reason to a stable HTTP status. Checks `user_is_filled` and
  refuses **503 `no_user_record` before any write** — because `accept_answer`
  writes the item first and the dual-signed `inbox_acceptance` needs the user/node
  keys; failing after the write would leave an item with no trail and a re-delivery
  refused as a duplicate. Dry-run verifies without writing (`RFI_VERIFIED_DRY_RUN`).
- **Signer op (master):** `sign-rfi-answer` derives `content_sha256` from the
  decoded payload (never trusts a caller digest), refuses a traversing `item_name`
  / malformed payload, records a `signature_issued` block. Docstring table 5→6.
- **Composer (master):** `master-node/scripts/sparknet-rfi-answer.sh`
  (`make -C master-node rfi-answer`) — signs (signer socket or `--offline`),
  **self-checks with the receiver's `verify_rfi_answer`** using `now=` the
  artifact's own `answered_at` (structural, not freshness), resolves the peer from
  the signed registry (refuses revoked/unknown), pushes like
  `sparknet-registry-deliver.sh`. Does **not** gather (4223 is spec-only).
- **Contracts flipped:** `rfi-schema.json` implementation_state (listener/composer/
  signer_op implemented; request_channel NOT BUILT + reason); `ports.json` 9090
  note names all three routes; `tracking-schema.json` phase_boundary (answer leg →
  `built_here`; `not_built` narrowed to email + request channel + dispatch-bridge-
  as-server); `provenance-protocol.md` and `peer-node/00_System/alpha-agent.md`
  updated to match.

## 68A — attribution decision (the blocker)

A request "signed with the peer's node key" is **unverifiable**: nothing binds a
fingerprint → node signing pubkey. The identity carries a Curve25519 WireGuard key
(can't verify Ed25519); the peer's Ed25519 node key (`ed25519-node.key.b64`) has its
public half in neither the identity, the registry entry, nor the trust root. And the
Master has no implemented peer-facing listener.

**Two options:**
- **C — attest `node_pubkey_b64` in the signed envelope** (like `department` in 66A).
  Matches the contract's rationale, but is a **two-repo** change (envelope is Python
  here + **Go in goSpark**; `test_registry_crossverify.py` pins agreement) that
  **compounds the re-sign already pending from 66A**. Rejected on blast radius.
- **B — attribute by the authenticated overlay (CHOSEN).** WireGuard already
  authenticates each peer; the Master's registry maps `overlay_ipv4 → fingerprint`.
  **On the overlay the tunnel is the identity.** Single-repo, reversible, no
  migration, goSpark untouched. C stays the recorded upgrade path.

Wrote `RFI_REQUEST_DESIGN.md`; rewrote `rfi-schema.json`'s `request` block to
Option B; moved `implementation_state.request_channel` `NOT BUILT → IN PROGRESS`.

## 68B — the request envelope

`build_rfi_request` + `verify_rfi_request` in `shared/sparknet-authz.py`, and
**deliberately no `sign_rfi_request`** (a test fails if one appears — an unverifiable
signature is theatre). `verify_rfi_request` is a **validator + fingerprint match**:
takes the overlay-derived `expected_fingerprint`, checks exact field set, fingerprint
match (`wrong_peer`), expiry (`expired`), future-issue (`not_yet_valid`), nonce replay
(`replayed_nonce`). `nonce`+`expires_at` are the replay guard. `build_rfi_request`
sorts+dedups `scope`, refuses an empty `question`. Never raises. 9 mutation-shaped tests.

# Step 69C — the Master peer-intake listener (8090 re-scoped)

## Built

`master-node/services/sparknet-telemetry-intake.py` — binds `10.100.0.1` only
(refuses a wildcard, like the reflex broker), serves `POST /api/v1/telemetry`.
The source gate is **registry-driven**: `PeerDirectory.attribute` maps the
WireGuard-authenticated source address → the Master's signed registry entry and
refuses *before the body is read*:
- unregistered source → `off_overlay`
- revoked → `revoked`
- no `telemetry` capability → `capability_missing`  ← this is "wire the telemetry
  capability" made concrete; the push gate (`telemetry`, peer-held) is distinct
  from the pull feed's (`admin-supervise`, Master-held).

Then `verify_telemetry_report(report, expected_fingerprint=<derived>)` — a report
naming another peer is `wrong_peer`. Attribution is the overlay (68A Option B); no
signature to forge. Accepted reports → `/mnt/log/sparknet-telemetry.jsonl` (0600,
canonical telemetry placement) with in-memory nonce replay protection. **No
authority**: `test_the_intake_carries_no_authority` source-scans for any signing
primitive. Unit staged via `make telemetry-intake-unit`, **not enabled** (operator
decision, like the signer/reflex units).
