## Decisions (operator, before code)

  peer→Master *request* is signed with the peer's node key, but **nothing binds a

  The composer takes `request_id` + destination peer as inputs instead. The reason
  is recorded in `rfi-schema.json` `implementation_state.request_channel` so it
  cannot be silently dropped.

  `--offline`. Added a `sign-rfi-answer` op to `sparknet-signer.py`.

## What was built

- **Listener (peer):** `POST /api/v1/rfi` is a *third route on the guard's 9090*,
  not a new port — `handle_rfi` in `peer-node/services/sparknet-guard-d.py`,
  behind the guard's source gate / size limit / refusal vocabulary, installing
  through `shared/sparknet-rfi-install.py::accept_answer` (the one rule). Not
  gated on the peer's capability (like the registry route). `RFI_REFUSAL_STATUS`

## 70B — the RFI request route; the intake is renamed

### What was built
`POST /api/v1/rfi-request` is a second route on the 8090 peer intake. It shares the
body reader and the registry source gate but **not** the `telemetry` capability:
`PeerDirectory.attribute(client, *, capability=...)` lets telemetry pass
`"telemetry"` and the request route pass `None`. The overlay still authenticates the
source, and `verify_rfi_request` still refuses a body whose `peer_fingerprint`
disagrees — no capability, not no attribution.

A verified request is queued as **one artifact per request**, named by the SHA-256 of
its canonical JSON (never the peer-chosen `request_id`), written atomically at 0600
into `/mnt/log/sparknet-rfi-requests` (0700). The nonce set is seeded from that
directory, so replay is refused before a second file can exist. A queue write failure
returns 503 rather than a false ack. The route answers nothing and the source scan now
fails on `build_rfi_answer` as well as the signing primitives.

## 70C — the composer consumes a verified request

### Built
`--request <artifact>` on `sparknet-rfi-answer.sh`. It re-verifies the queued request
(shape, freshness, nonce format) and takes `request_id`/`peer_fingerprint` from the
request, not from operator flags. The operator path stays and is mutually exclusive.

`--sources` declares the vault categories the upstream gatherer used. With
`--request`, content requires at least one source, every source must be in the
request's `scope`, and an empty answer declares none; an out-of-scope source is
refused. This is the enforceable half of scope — the declaration is the gatherer's
attestation, not something the channel can independently prove.

## 70E — checkpoint anchor

### Built
`peer-node/services/sparknet-checkpoint-anchor.py` verifies the ledger, then appends a
`checkpoint` block only when the head has moved and pushes the **full signed block** as
`kind=checkpoint_anchor` through 70A. Payload is `{"checkpoint": block}` so the Master
can run `provenance.verify_checkpoint` rather than trust three numbers.

### The idempotence trap
`build_checkpoint_data` snapshots the chain *before* the checkpoint is appended. After
the first append, the checkpoint is the newest block, so a naive re-run sees
`size + 1` every time and appends forever. The service handles the current-head case:
the newest block is a checkpoint whose `data.size` equals the number of blocks before
it, whose `head_hash` is that block's hash, and whose `root` re-computes over them.
Then it writes nothing and re-pushes the same signed block (evidence refresh, no new
state). A chain that grew past that checkpoint gets a new one.

Empty ledger = exit 0 with a reason; tampered chain = exit 1 without appending;
`--dry-run` writes nothing. Unit is oneshot + 15-minute persistent timer, wired at all
three installer points.
