# 2026-11-11 — deep-module audit remediation

## Outcome

Closed the seven findings from
`docs/architecture/2026-11-10-deep-module-audit.md`. The local issue tracker is
at `.scratch/issues/` with all seven entries `done`.

- **Go capability drift.** `gospark/internal/authz/capabilities.go` now carries
  `issue-report` and `sandbox-supervise`; `sandbox-supervise` is sensitive. The
  Go known/sensitive/Master-implied sets are pinned to
  `contracts/capabilities.json` by `tests/test_capability_catalog.py`, and both
  new capabilities cross the Python/Go boundary in
  `tests/test_registry_crossverify.py`.
- **Registry acceptance.** `shared/sparknet-authz.py::accept_entry` is the one
  rule for a remote entry; `evaluate` delegates to it. Peer liveness, Master
  peer intake, scheduler, RFI responder and uplift intake map its typed refusal
  codes to their existing HTTP vocabulary.
- **Loader resolution.** `shared/sparknet_loader.py` owns
  `SPARKNET_SHARED_DIR` (directory or root), `SPARKNET_FABRIC_ROOT`,
  `VAULT_PATH`, role/bundle layouts and `/srv/sparknet/shared`. The role-service
  resolvers are gone; `tests/test_loader_contract.py` fails if one returns.
- **Console vector view.** `shared/sparknet-vector-view.py` owns the stdlib-only
  read path and the collection stamp; the console reports `stamped`/`unstamped`.
- **Contract tests.** `tests/contracts/` holds one module per contract
  boundary; `tests/test_contracts.py` is a thin inventory marker.
- **Package artifacts.** `shared/sparknet-package.py` owns the directory walk
  and contract excludes; the CLI is argument parsing.
- **Authz decision.** `docs/adr/0014-keep-authz-behind-one-facade.md` keeps the
  module whole for this release and records the staged-split trigger.
