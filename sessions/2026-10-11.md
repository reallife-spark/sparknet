### Findings that changed committed code

- **Python 3.8 blocker (found, fixed).** Node runtime is 3.8.10. The bundle's
  bridge could not import: `sparknet-dispatch-bridge.py` lacked
  `from __future__ import annotations` and `collections.abc.Callable` does not
  exist on 3.8. Fix: future-import in the bridge; portable
  `try collections.abc → typing` `Callable` fallback (with `# noqa: UP035`) in
  the bridge, `sparknet-http.py`, `sparknet-consensus.py`,
  `sparknet-liveness.py`, `sparknet-election.py`, `sparknet-share-regime.py`.
  Lint clean; peer suite still 356 passed / 1 skipped.
- **Network-mode decision (user-confirmed 2026-10-11).** The committed compose
  used bridge-network + `host.docker.internal:host-gateway`; a bridge-network
  container cannot reach the loopback-only dispatch bridge on the published form
  chosen. Operator chose **`network_mode: host`** for `open-webui` (go→lan
  reachability + bridge reachability in one move), all URLs now
  `http://127.0.0.1:…` (`:11434` ollama, `:18000` chroma, `:4096/v1` bridge),
  `PORT=8181`. Compose/manifest/README/`test_node_ai_stack.py` updated.
- **Firewall self-heal gap (found, fixed).** `sparknet-firewall.service` was
  `After=docker.service` — fine at boot, but a `systemctl restart docker`
  recreates `DOCKER-USER` and loses the rule. Added `PartOf=docker.service` so a
  docker restart re-runs the unit. Verified on `.133`: after `systemctl restart
  docker`, unit active and 3 `SPARKNET-FW-FWD` jumps back in `DOCKER-USER`.
  `test_firewall.py` asserts `After` + `PartOf`.

### Open WebUI 0.12 nuances found live (additions to the API notes)
- List endpoints are envelopes: `users`→{users,total}, `knowledge`→{items,total},
  `files`→{items,total}; `skills`/`tools` are bare arrays.
- KB delete route is `/knowledge/{id}/delete` (bare `/{id}` = 405); for KBs the
  files listing paginates at `limit=30` **even for admins** unless limit passed.
- Upload+add race: `process=true` embeds in a background task; the immediate
  `file/add` 400s "The content provided is empty". Fix: upload `process=false`,
  then synchronous `POST /retrieval/process/file`, then `file/add`.
- `file/add` re-processes into the KB vector collection and **blocks content
  whose hash already exists under a different file_id**
  (`has_duplicate_content`; retrieval.py). Fix: reuse the global file record by
  content sha256 via `GET /files/` so re-adds reindex instead of 400ing — one
  file record per page, rebuilds stay idempotent.
- `directory_id` is accepted at `file/add` time, so pages land in their numbered
  dir in one pass (no separate move stage).
- Tool servers only surface in `/v1/tools/` when the connection carries
  `config.enable: true` (`get_tool_servers_data` filter).
- `/configs/models` must round-trip the full body; `DEFAULT_PINNED_MODELS` is a
  string (`""` ok, `[]` → 422).
- Known 0.12 bug: `delete_knowledge_by_id` crashes with
  `'str' object has no attribute 'get'` (knowledge.py ~1743) when any model row
  has a non-empty `meta.knowledge` list — meta stores string ids but the loop
  calls `.get('id')`. Worked around on .133 by deleting the fresh per-user model
  row (SQLite, backed up) so KB deletes proceed; .131 already had no model rows.
- Compose plugin is user-scoped on the nodes: root must
  `sudo DOCKER_CONFIG=/home/raxxar/.docker docker compose …`.
