### Contract conformance — the missing keystone

`make contract-test` pointed at `peer-node/tests/test_contracts.py`, which was
never written, so the target had always failed. Wrote `tests/test_contracts.py`
(26 tests) pinning the contract against its consumers:

- the shared implementation exists exactly once, and its `KNOWN_CAPABILITIES`,
  `IDENTITY_FIELDS`, `SIGNED_FIELDS`, `SCHEMA_VERSION` equal the contract's lists;
- `capabilities` and `revoked` are inside the signed envelope, so registry write
  access cannot escalate or reinstate;
- overlay addressing: the Master is the anchor, the peer range excludes it and the
  broadcast, a peer is a `/32`, and both templates use the contract MTU;
- ports: guard 9090 owned by the peer, instant-push 8090 owned by the Master, no
  service claims two ports, unimplemented ports declare themselves SPEC ONLY;
- the role vocabulary is exactly `{master, peer}`.

### Shell bug worth remembering

`scripts/sparknet-env-init.sh` grew `if [ -n "$_stale" ]]; then` — a doubled
`]`. **`bash -n` accepts it**: bash reads `]]` as an ordinary argument to `[`, so
the script parsed, linted, and passed every check, then failed at runtime with
`line 90: [: missing ']'`. It only fired on a branch nothing exercised. Added
`tests/test_shell.py`, which strips quoted text, `=~` regex operands and array
subscripts before looking for the doubled closer — every one of those is full of
brackets and produces false positives if you look naively.

### Relocatability

Ran the tree from four different paths, which is the only way to actually test
the central claim. Three real bugs:

1. **`sparknet-wiki-env.sh` recomputed `_expected_env` from `$_role_root`**,
   which is empty at the fabric root, so it compared the resolved `.env` against
   `/.env` and refused a correctly configured session.
2. **`sparknet-env-init.sh` detected the fabric root by directory name.** A clone
   called anything else was rejected. Now structural: it holds `contracts/` plus a
   role.
3. **A copied `.env` kept the old `VAULT_PATH` and was preserved** because it had
   a `VAULT_PATH`, so a moved tree stayed broken. An `.env` naming some other
   directory is stale, not user intent, and is now regenerated with a message
   saying why.

It was the **cluster** KillSwitch: root-gated, and with all five teardown steps

## Gotchas

- `rm -rf` on some paths is blocked by tool policy — use `mktemp -d`.
- `bash -n` is not a shell test. It validates grammar, not semantics.
- Grepping for `]]` to find shell bugs is hopeless until you strip quoted strings,
  `=~` operands and `${arr[@]}`.
- The relocation test is what found the dangling links and phantom directories.
  Every future structural change should be re-verified from an extracted copy.
