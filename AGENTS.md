# sparknet — agent charter

sparknet is a two-role fabric. A **peer** is the user's local AI node: chat,
agentic planning/building, a private vault and self-healing. A **Master** is the
elected signing role: it holds the operational key and supplies authority and
scoped fabric knowledge. It does not run a peer's model or choose a user's work.

Read `CONTEXT.md` first. It is generated from this charter, `MISSION.md`,
`INTENT.md` and `contracts/knowledge-flow.md` and is loaded by every AI surface.
`AGENTS.md` wins on conflict; `contracts/` wins over prose.

## The fabric

| Path | Role | State |
|---|---|---|
| `contracts/` | both | single source of truth: overlay, capabilities, identity, ports, registry, guard, share, consensus, health, telemetry, RFI, knowledge flow |
| `shared/` | both | `sparknet-authz.py` and the one shared implementation of provenance, consensus, registry install, RFI install, liveness, notify, and the memory gateway |
| `peer-node/` | peer | implemented: guard, anchor, dispatch bridge, AI stack, per-user vaults, self-healing |
| `master-node/` | master | built: parity loader, ledger, isolated signer, registry, approvals, intake, admin console, responder |
| `goagx/` | both | AGX Xavier node image surface and standalone distribution |
| `gospark/` | both | separate Go control/service-plane checkout; gitignored, gated in place |
| `.opencode/skills/` | both | vendored wiki suite; role catalogs live under `<role>/.opencode/skills/` |

A role subvault alone is **not** a deployment. `make bundle` assembles what a
node needs; `bundle-verify` proves it runs elsewhere.

## Knowledge flow

`contracts/knowledge-flow.md` is the map. The rule:

> Authority and knowledge travel on separate channels. No channel both grants a
> capability and carries content an AI may treat as knowledge.

A peer answers from its vault, its user's KB, an accepted RFI answer, a
reconciled share or the build-time context pack. Registry entries, approvals,
telemetry and admin responses are never knowledge. Scope narrows, never widens.
Personal pages never enter a shared corpus. The full channel table, including
`4221`/`4223` as spec-only, is in that contract.

## Context

`CONTEXT.md` is generated by `scripts/sparknet-context-pack.py`. Run
`make context-pack` after changing `MISSION.md`, `INTENT.md`, `AGENTS.md` or
`contracts/knowledge-flow.md`; `make context-check` fails when it is stale.
Never hand-edit it. It is loaded by OpenCode, the Open WebUI structure KB,
per-user KBs/models, the vLLM/MASTERSPIKE precontext and the admin terminal.

## Memory Protocol

- `MEMORY.md` — standing state only, tiny: plan pointer, durable facts,
  blockers, local-vs-live. Replace, never append.
- `sessions/YYYY-MM-DD.md` — that session's full record. One file per day;
  sessions spanning midnight use the start date.
- Typed memory is a per-vault index over the vault, sessions, skills and
  delegate runs: episodic, semantic, procedural, short-term and shared. It is
  not a second vault. The Go store (`sparknet-memory`, loopback `4110`) holds no
  key; the Python gateway (`4093`) verifies the session and narrows to one
  vault. OpenCode and Open WebUI are adapters over the same store.
- Read `CONTEXT.md`, `AGENTS.md`, `MISSION.md` and `INTENT.md` at session start,
  then `MEMORY.md` and today's session file. Write detail only to today's file.
  Never back-write history into `MEMORY.md`.

## Plan Protocol

`PLAN.md` is the single source of truth for fabric work. `peer-node/PLAN.md` and
`master-node/PLAN.md` own role work; do not duplicate steps across them.

- Frontmatter `current:` marks the step being worked.
- Mark `[x]` **only** after its DoD is verified, then advance the cursor and
  write the plan back **immediately**.
- Append one line per transition to `log.md`.
- Terminal state is `current: done`. New work gets a **new** step.
- A DoD that cannot be auto-verified is `DoD: confirm: user`.

Run everything through `make`. `scripts/sparknet` is the unified CLI;
`SPARKNET_DRY=1` prints the invocation. `make nv-search q="…"` is the
resource-first check before building a container or model.

## Work discipline

`STYLE_GUIDE.md` is the standing convention: Python, shell, Makefiles, commits,
secrets, CI, docs, release. Its §1 is resource-first: check NVIDIA's catalog
before building your own. Cross-role changes are atomic: edit `contracts/`,
`shared/` and both roles in one commit, then `make contract-test`.

## Layout

Vault categories: `concepts/`, `entities/`, `skills/`, `references/`,
`synthesis/`, `journal/`, `projects/`, `sessions/`, `_raw/`, `_staging/`,
`_archives/`. Role subvaults keep the numbered PARA layout with legacy names as
symlinks. Distilled page → its category; raw capture → `_raw/`; logs → `/mnt/log/`;
secrets → the node's state directory. One page per file; cross-link instead of
copying.

## Boundaries

- **Scope.** Fabric knowledge here; role knowledge in that role's vault; user
  knowledge in the user's `peer-<id>` vault/KB.
- **No secrets.** Never commit or echo keys, tokens or `.env` values; reference
  the path only. Uplift traces and raw-KV artifacts are redacted before dataset
  build; a secret that reaches them is a leak, not training data.
- **Uplift is not knowledge.** A consented Qdrant snapshot, trace or KV
  manifest is training/backup data on the Master. It never enters `4223`, a
  vault, an RFI answer or a user's AI context.
- **Offensive security is out of scope** for a default session. Route offensive
  work to `red`, defensive to `blue`.
- Cite sources. A distilled page without provenance is a guess.
- **No live-verification claims** from a development host. Say "implemented and
  tested", "deployed live on <host> on <date>", or "unverified here".
