## The two roles

- **`peer-node/`** — implemented: guard, anchor, dispatch bridge, agent ports,
  containment. [`peer-node/AGENTS.md`](peer-node/AGENTS.md)
- **`master-node/`** — built (Steps 15–18): `scripts/`, `services/`,
  `systemd/`, `manifests/`, `blockchain`, `security`; isolated signer deployed
  as `sparknet-master-signer.service` on agx64, election proven live 2026-10-07. 
  [`master-node/AGENTS.md`](master-node/AGENTS.md)

Authority comes from **key possession**, not a capability grant: a peer with the
whole vocabulary but no private key can never grant, revoke or escalate.

## Maintenance

Run `make wiki-preflight` first: it proves the vendored skills will resolve
*this* vault. A failure there is not something to work around — the skills would
silently write into a different vault.

| Command | Purpose |
|---|---|
| `make wiki-verify` | the vendored suite still matches its pinned upstream |
| `/wiki-status` | ingest delta + recommendation |
| `/wiki-lint` | health audit (orphans, stale, broken links) |
| `/wiki-query` | ask the wiki, with citations |
| `/daily-update` | daily cycle: index + hot cache refresh |

## Repo-wide checks

| Command | Purpose |
|---|---|
| `make test-all` | every suite: contract, fabric, peer, master |
| `make contract-test` | the peer still matches `contracts/` |
| `make lint` | ruff over everything linted |
| `make bundle ROLE=…` | build a standalone node bundle |
| `make bundle-verify ROLE=…` | extract it elsewhere and prove it runs |

## Release surface

The unified `scripts/sparknet` CLI routes each command to its `make` target
(`sparknet version`, `sparknet test`, `sparknet bundle peer`, …).

| Path | Holds |
|---|---|
| `VERSION` | the fabric version — the single source of truth for `pyproject.toml` and the SBOM |
| `sbom/sparknet.cdx.json` | generated CycloneDX SBOM (`make sbom`; `make sbom-check` gates drift) |
| `scripts/sparknet-sbom.py` | the deterministic SBOM generator (mirrors `scripts/sparknet-render.py`) |
